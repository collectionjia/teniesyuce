# 网球产品说明（盘前 / 盘中 / 盘后 · 全链路 · 展示 · 条件与引擎）

生成时间：2026-09-09  
本文为网球相关**唯一汇总文档**（**目标架构 To-Be**）。  
现网若仍为 `tennis-range` / `tennis-live` / `tennis-new` / `tennis-inplay` 等旧键，**迁移完成前以代码为准**；策略与产品口径以本文为准落地。

## 产品定义（以本说明为准）

网球**对外共三个产品**（均以北京时间「今天」为日界）：

| # | 产品名 | 覆盖范围 |
|---|--------|----------|
| 1 | **盘前网球** | **今天（北京时间 0:00–24:00）** 内的 **未开赛** 赛事，且 **强者现排 ≤ 100** |
| 2 | **盘中网球** | **今天（北京时间 0:00–24:00）** 内的 **进行中** 赛事，且 **强者现排 ≤ 100** |
| 3 | **盘后网球** | **今天（北京时间 0:00–24:00）** 内的 **已结束** 赛事，且 **强者现排 ≤ 100** |

时区约定：

- 「今天」= **Asia/Shanghai（北京时间）** 的自然日，到 **24:00** 截止。  
- 过了北京时间 24:00 即进入「明天」，赛程归属按新自然日切。

排名约定（统一口径）：

- **强侧 / 弱侧**：双方中 **现排名更好（数字更小）** 的一侧为强者；另一侧为弱者（现排不会并列，无需打破规则）。  
- **Top100 = 强者现排 ≤ 100**（不是「任一方 Top100」）。进三桶、列表默认「强现」、采集过滤，均按此口径。  
- **现差** = **弱者现排名 − 强者现排名**（≥0；越大表示强弱现排拉开越多）。  
- **排差** = **强者现排名 − 弱者历史最高排名**（可为负；&lt;0 表示强者现排仍优于弱者历史巅峰）。  
- 列表 chip「现差≥N / 排差&lt;0 …」均按上式计算后再比阈值。

### 盘后与盈亏统计（产品要求）

在 **盘前网球**、**盘中网球** 上发生的投注，赛果落定后须在 **盘后网球** 页同时统计出：

| 统计块 | 内容 |
|--------|------|
| **合计** | 今日已结算总投入、总盈亏、**盈利比**、**亏损比** |
| **盘前盈亏比** | 仅统计在 **盘前网球** 下单的已结算成交 |
| **盘中盈亏比** | 仅统计在 **盘中网球** 下单的已结算成交（含止损卖出） |

| 指标 | 含义（已定口径） |
|------|------------------|
| **盈利比** | **盈利笔数 ÷ 已结算笔数** |
| **亏损比** | **亏损笔数 ÷ 已结算笔数** |
| **总投入 / 总盈亏** | 金额另列；不用于计算盈利比、亏损比 |
| **已结算** | 持有至赛果结算，**或**盘中止损卖出已平仓——二者均计入已结算笔数与最终盈亏；**不设第三类** |
| **一笔** | 同一用户下，按 **`eventId` + `product`** 聚合成的一个仓位（买+卖/结算算 1 笔，不是流水条数） |
| **盈 / 亏笔** | 该笔最终盈亏金额 &gt; 0 为盈；&lt; 0 为亏；= 0 计入已结算但不计入盈/亏笔（盈+亏≤已结算） |

要求：

- 盘后页必须 **并列展示**：合计 + 盘前分项 + 盘中分项（不能只给一个总数）。  
- 按 **北京时间今天** 汇总；可下钻到单场。  
- **日界**：以该笔 **结算完成日**（持有至赛果的结算日，或止损卖出成交日）的北京时间自然日计入；跨日持仓记入结算发生日，不记入开仓日。  
- **stats** 以当日已结算 `tradeRecords` 为准，**不因**该场是否仍在 `settled` 列表桶内而丢弃；列表展示读桶，统计读成交。  
- 列表行可与盘后赛事按 `eventId` 关联展示「盈 / 亏 / 未投」。  
- **盘后网球本身不再新开仓**，以赛果展示与盈亏复盘为主。  
- 某日某桶可为空（例如仅有 settled、盘前/盘中无场），列表与统计按空集处理即可。

产品 **tag / product 字段** 与三桶一一对应（不再使用旧的 tennis-range / tennis-new / tennis-live 等）：

| 产品名 | tag / product | Redis | 展示接口 | 下单接口 |
|--------|---------------|-------|----------|----------|
| 盘前网球 | `tennis-prematch` | `tennis:bundle:prematch` | `GET /api/tennis-prematch/today` | `POST /api/tennis-prematch/trade/batch` |
| 盘中网球 | `tennis-inplay` | `tennis:bundle:inplay` | `GET /api/tennis-inplay/today` | `POST /api/tennis-inplay/trade/batch` · `.../trade/sell` |
| 盘后网球 | `tennis-settled` | `tennis:bundle:settled` | `GET /api/tennis-settled/today` · `.../stats` | **无下单**（只读复盘） |

### 采集与存储（目标架构）

**一次采集**，按状态拆成 **三个变量 / 三个 Redis 键** 分别存储：

| 变量（逻辑名） | Redis 键 | 内容 |
|----------------|----------|------|
| `prematch` / 盘前 | `tennis:bundle:prematch` | 今天 · 未开赛 · 强者现排≤100 |
| `inplay` / 盘中 | `tennis:bundle:inplay` | 今天 · 进行中 · 强者现排≤100 |
| `settled` / 盘后 | `tennis:bundle:settled` | 今天 · 已结束 · 强者现排≤100 |

流程：

```
全量采集（经 IPWO 采集 https://www.sofascore.com/tennis → 强者现排≤100）
    ├─► tennis:bundle:prematch   （未开赛）
    ├─► tennis:bundle:inplay     （进行中）
    └─► tennis:bundle:settled    （已结束）
```

说明：

- **全量采集数据源**：经 **IPWO** 采集 [Sofascore 网球](https://www.sofascore.com/tennis) 页面数据，再按状态拆三桶。  
- **同一轮采集写三个桶**；三产品分别读各自变量；某桶当日无场可写空列表。  
- 附属 map（`rankingsByPlayer` / `oddsByEvent` / `polymarketByEvent` 等）**共享一份** `tennis:bundle:meta:today`（三桶只存各自 `matches`；排名/赔率/PM 走 meta）。  
- `tradeRecords.product` 只使用：`tennis-prematch` | `tennis-inplay`（盘后统计按此分项）。  
- **盘中按秒 tick** 不走 IPWO/Sofascore，而是 **直连 Polymarket 网站** 采盘中价（见 §2.4）。

### 引擎与权限（管理员统一管理）

三类引擎统一放在 **管理员后台** 配置与启停；普通用户 / 代理 **不能改规则、不能开关引擎**。

| 引擎 | 职责 | 管理员可做 |
|------|------|------------|
| **采集引擎** | 全量（IPWO→Sofascore）拆三桶；盘中 tick（直连 Polymarket）；盘前→盘中时间迁桶；结束→settled | 启停、间隔（含 `inplay_tick_interval_sec`）、监控 |
| **条件引擎** | 按管理员配置的筛选规则决定「哪些场进入可见/可交易候选」 | 配置规则；**条件打开 / 关闭** |
| **投注引擎** | 按管理员配置的买入/止损规则自动下单（盘中见 §九；盘前若配置则同样走本引擎） | 配置规则；**投注打开 / 关闭** |

**列表谁能看：**

| 角色 | 盘前 / 盘中 / 盘后列表 |
|------|------------------------|
| 用户 | ✓ 可看 |
| 代理 | ✓ 可看 |
| 管理员 | ✓ 可看 |

**开关与生效：**

| 开关 | 关闭时 | 打开时 |
|------|--------|--------|
| **条件打开** | 列表按桶原始数据展示（仍可有用户本地 chip 二次筛，不改桶） | 列表（及交易候选）按 **管理员条件引擎规则** 筛选后再展示 |
| **投注打开** | 不自动下单；用户仍可手动下单（盘前/盘中有下单口时） | 按 **管理员投注引擎规则** 自动筛选并投注（含盘中止损）；规则未命中则不下单 |

```
管理员后台
  ├── 采集引擎（启停 / 间隔）
  ├── 条件引擎（规则 + 【条件打开】）──► 打开后：按管理员规则筛选列表
  ├── 投注引擎（规则 + 【投注打开】）──► 打开后：按管理员规则自动投注
  ├── 调度中心（采集/投注任务编排 · 立即执行可并行）──► 配置存 MySQL
  └── API 对外中心（/api/engine/*，凭 API Key，不按角色）
用户 / 代理 / 管理员 ──► 均可看三产品列表
```

约定：

- 规则与开关 **仅管理员** 可改；用户/代理只消费结果。  
- **投注打开** 隐含依赖采集在跑；盘中策略还依赖 tick。  
- **条件打开** 与 **投注打开** 可独立：可只开条件看筛选列表、不开自动投注；也可只开投注——**下单不依赖条件引擎**，直接对采集桶用投注规则过滤。  
- 投注引擎打开时，执行口径以管理员当前规则为准（盘中默认对齐 §九）；与用户本地列表 chip **无关**——chip 只影响个人看见什么，不放宽/收紧自动投注。  
- **调度中心 / API 对外中心** 目标设计见 [`调度中心与API对外中心-设计.md`](./调度中心与API对外中心-设计.md)（配置 MySQL；立即执行与定时可并行；`/api/engine/*` 凭 API Key，不按角色）。

# 一、盘前网球全链路

## 1.1 产品

- **产品名：盘前网球**  
- **tag / product：`tennis-prematch`**  
- 范围：北京时间「今天」的 **未开赛** 赛事，且 **强者现排 ≤ 100**  

| 项 | 值 |
|----|-----|
| 变量 / Redis | `prematch` → `tennis:bundle:prematch` |
| 展示接口 | `GET /api/tennis-prematch/today` |
| 下单接口 | `POST /api/tennis-prematch/trade/batch` |
| 看板 | `TennisBoard` · `board-mode="prematch"` |

登录可看（**用户 / 代理 / 管理员**）；下单需钱包。  
采集 / 条件 / 投注三引擎见文首「引擎与权限」——**仅管理员**可配置与开关。

## 1.2 采集与存储

- 来自**同一次采集**写入的 **`tennis:bundle:prematch`**  
- 内容：**北京时间今日 + 未开赛 + 强者现排≤100**

### 1.2.1 开赛时间过后迁入盘中

- 盘前桶内场次，若 **赛事开赛时间已过**（相对当前北京时间）：**立即迁入** `tennis:bundle:inplay`，并从 `tennis:bundle:prematch` **删除**。  
- 不等待下次全量把状态标成「进行中」才搬家；**以开赛时间是否已过为准**。  
- 迁入后按盘中产品展示与 tick（直连 Polymarket）刷新；强者现排仍须 ≤100（不满足则不入 inplay，可暂留处理或丢弃，实现时与采集过滤一致：一般开赛前已是 Top100）。

## 1.3 显示 / 下单

列表：今天·未开赛·强者≤100；可再筛巡回、PM、现差等。  
勾选有 PM、建议侧 → `POST /api/tennis-prematch/trade/batch` → `tradeRecords.product = tennis-prematch`。  
手动下单需钱包；**自动投注**仅当管理员 **投注打开** 且命中管理员投注规则时执行（盘前规则若未配置则不开自动买）。  
**结算后计入盘后「盘前盈亏比」。**  
开赛时间一过，该场从盘前列表消失，出现在盘中。  
管理员 **条件打开** 时，列表按条件引擎规则筛选后再展示。

## 1.4 简图

```
一次采集 → tennis:bundle:prematch
  → GET /api/tennis-prematch/today
  → POST /api/tennis-prematch/trade/batch
  → 开赛时间已过 ──立即──► tennis:bundle:inplay（并从 prematch 删除）
  →（赛果后）盘后 · 盘前盈亏比
```

# 二、盘中网球全链路

## 2.1 产品

- **产品名：盘中网球**  
- **tag / product：`tennis-inplay`**  
- 范围：北京时间今天 · **进行中** · **强者现排 ≤ 100**  

| 项 | 值 |
|----|-----|
| 变量 / Redis | `inplay` → `tennis:bundle:inplay` |
| 展示接口 | `GET /api/tennis-inplay/today` |
| 买入接口 | `POST /api/tennis-inplay/trade/batch` |
| 止损接口 | `POST /api/tennis-inplay/trade/sell` |
| 看板 | `TennisBoard` · `board-mode="inplay"` |
| 谁能看 | **用户 / 代理 / 管理员**（同盘前） |
| 引擎 | 采集·条件·投注均在 **管理员** 下统一管理；条件/投注可分别打开 |

## 2.2 采集 / 显示 / 下单

- 同轮**全量采集**（IPWO → Sofascore 网球）中状态=进行中且强者现排≤100 → 写入 **`tennis:bundle:inplay`**  
- **盘前开赛时间已过**的场：按 §1.2.1 **立即从 prematch 迁入 inplay**（并删 prematch）  
- 另有 **按秒 tick**（见 2.4）：**直连 Polymarket 网站** 刷价；符合条件的新盘口直接入桶；结束则立即迁 settled 并移出 inplay  
- 列表：强现≤100；现差可选不限/分档达标；前端读刷新后的 inplay 桶  
- **自动买 / 止损：** 见 [§九](#九下注引擎策略执行)；须管理员 **投注打开**，规则以管理员配置为准（默认对齐 §九）  
- 管理员 **条件打开** 时，列表按条件引擎规则筛选  
- `tradeRecords.product = tennis-inplay`；**结算后计入盘后「盘中盈亏比」**

## 2.3 简图

```
全量（IPWO → sofascore.com/tennis）→ tennis:bundle:inplay
盘前开赛时间已过 ──立即──► inplay（prematch 删除）
按秒 tick（直连 Polymarket 网站）──► 刷价 · 新进直接入桶 · 结束迁 settled
  → GET /api/tennis-inplay/today
  → POST /api/tennis-inplay/trade/batch | trade/sell
  →（赛果后）盘后 · 盘中盈亏比
```

## 2.4 盘中按秒轻量更新（赛中 tick）

在全量采集之外，对盘中做高频增量。与全量不同：**tick 不经 IPWO、不采 Sofascore**，而是 **直连 Polymarket 网站** 采集盘中数据（主要为 moneyline 价格等）。

| # | 字段 | 用途 |
|---|------|------|
| 1 | **Polymarket 赔率** | 已匹配外链场次的 moneyline 价格（¢）等盘中价 |
| 2 | **比赛状态**（若 PM 页/接口可得） | 是否仍进行中 / 是否已结束（结束后 **立即** 迁入 settled） |
| 3 | **比赛比分**（若 PM 页/接口可得） | 盘分、局分等；供 §九 止损判断 |

> 对阵、排名、首次 PM 匹配关系等仍以 **全量（IPWO → Sofascore）** 建场为准；tick 只刷新已入桶场次的 PM 侧数据，并在 live 新匹配到的场次满足条件时 **直接入 inplay**。

### 原则

- **数据源**：直连 **Polymarket 网站**（非 IPWO、非 Sofascore）；固定请求路径便于限流与监控。  
- **已有场**：不重采 Sofascore 赛程池/出生年等；只 **patch** PM 价（及 PM 侧可得的状态/比分）。  
- **新进场**：本轮 tick 在 Polymarket 侧发现、且能对齐「北京时间今天 · 进行中 · 强者现排≤100」的场 → **直接写入 inplay**（排名须已在 meta/全量可得，否则本 tick 不入桶）。  
- 间隔按秒配置，**仅允许：`1` / `2` / `5` / `10`（秒）**；**默认 `5`**。  
- 配置项建议名：`inplay_tick_interval_sec`（写入调度/站点设置，与全量采集间隔分开）。  
- 无盘中场次时仍跑 tick（以便发现新进 PM 盘口）。  
- 若某场状态变为 **已结束**：**本轮 tick 内立即迁桶**——写入终分与状态到 `tennis:bundle:settled`，并从 `tennis:bundle:inplay` **删除**该场；不等待下次全量采集收口。

### 固定路径（约定）

| 角色 | 路径 | 说明 |
|------|------|------|
| 产品读 | `GET /api/tennis-inplay/today` | 前端仍读 inplay 桶（被 tick 不断覆盖） |
| 触发/内部 | `POST /api/tennis-inplay/tick`（或采集进程内循环，不对外） | 跑一轮轻量更新 |
| 全量（对照） | IPWO → `https://www.sofascore.com/tennis` | 建池、排名、三桶拆分；**tick 不走此路径** |
| Polymarket | **直连 Polymarket 网站**（按桶内已有 slug/url/event 页） | 刷 **价格**；新盘口符合条件则入 inplay；不再经 IPWO |

### 写入

**已有场** — patch（来自 Polymarket 直连）：

```
polymarketByEvent[id].prices  ← Polymarket 网站（保留 url/slug，只改价）
match.status / score*         ← 若 PM 侧可得则一并更新
fetched_at / tick_at          ← 本轮 tick 时间
```

**新进** — insert 进 `tennis:bundle:inplay`（今天 · 进行中 · 强者≤100），再按上式补价。

不改（已有场）：球员基本信息、排名 map 快照、首次 PM 匹配关系（无 slug/url 则本 tick 跳过该场 PM）。

### 与全量采集关系

| | 全量采集（一次拆三桶） | 盘中按秒 tick |
|--|------------------------|---------------|
| 数据源 | **IPWO → Sofascore 网球页** | **直连 Polymarket 网站** |
| 频率 | 分钟～小时级 | **可设 1 / 2 / 5 / 10 秒** |
| 范围 | 盘前+盘中+盘后 | **inplay 已有场 + PM 侧新进符合条件的场** |
| 内容 | 建池、强者≤100、PM 匹配、排名… | **PM 价**（及可得的状态/比分）；**新进直接入 inplay** |
| Redis | 写三键 | patch/insert `inplay`；结束则 **立即** 推 `settled` 并从 inplay 移除 |

# 三、盘后网球全链路

## 3.1 产品

- **产品名：盘后网球**  
- 范围：北京时间今天 · **已结束** · **强者现排 ≤ 100**  
- 定位：赛果复盘 + **同时输出合计、盘前、盘中三套盈利比/亏损比**（不是第三个开仓入口）

## 3.2 采集与列表

- **`tennis:bundle:settled`** 来源：同一次**全量采集**写入的已结束场，以及盘中 tick **立即迁入**的结束场（二者合并；同一 `eventId` 以最新终分为准）。  
- 内容：**北京时间今天 + 已结束 + 强者现排≤100**  
- 展示：对阵、最终比分、级别、排名；关联本场是否有本账户投注  
- **不提供**新的买入按钮（或禁用下单）

## 3.3 盈亏比统计（已定口径）

对「北京时间今天」**结算完成**、且来源于盘前/盘中产品的成交，在盘后页输出 **三块指标**：

| 块 | 口径 |
|----|------|
| 合计 | `tennis-prematch` + `tennis-inplay` 全部已结算 |
| 盘前盈亏比 | `product = tennis-prematch` |
| 盘中盈亏比 | `product = tennis-inplay`（含止损卖出） |

每块至少包含：

- 已结算笔数、盈利笔数、亏损笔数（**一笔** = `eventId` + `product` 仓位）  
- **盈利比** = 盈利笔数 ÷ 已结算笔数；**亏损比** = 亏损笔数 ÷ 已结算笔数（三块同一口径）  
- 总投入、总盈亏金额（金额与笔数比并列展示，互不替代）  

步骤：

1. 拉取用户当日已结算仓位（由 `tradeRecords` 的 buy/sell 按 `eventId`+`product` 聚合；含止损卖）。  
2. 用赛果/结算价或止损卖出价算最终盈亏；**stats 不依赖**该场是否出现在 `settled` 桶列表中。  
3. 按 `product` 分桶汇总后展示；列表行（桶内场）可显示该场「盈 / 亏 / 未投」及来源。

| API | 说明 |
|-----|------|
| `GET /api/tennis-settled/today` | 读 `tennis:bundle:settled`（列表） |
| `GET /api/tennis-settled/stats` | 读成交聚合 `{ total, prematch, inplay }` 各含盈利比、亏损比 |

## 3.4 简图

```
全量采集 + tick 迁入 → settled 桶 → 盘后网球列表
tradeRecords（按 eventId+product 成笔）
  ├── 盘前成交 → 盘前盈利比 / 盘前亏损比
  ├── 盘中成交 → 盘中盈利比 / 盘中亏损比
  └── 合计   → 合计盈利比 / 合计亏损比
```

# 四、条件过滤模块

三个产品列表共用一套 **条件过滤模块**。分两层：

1. **管理员条件引擎**（权威）：管理员配置规则 + **条件打开** 后，服务端/产品级按该规则筛选，用户/代理/管理员看到的列表都受此约束。  
2. **用户本地 chip**（可选二次筛）：个人偏好持久化；**不能**放宽管理员已关掉的场，也 **不能** 改变投注引擎行为。

## 4.1 职责

| 项 | 说明 |
|----|------|
| 管理员存什么 | 条件引擎规则、**条件打开**开关；投注引擎规则、**投注打开**开关（后台） |
| 用户存什么 | 各产品本地筛选值（巡回、PM、强现、现差…）作二次视图 |
| 何时用 | 进入列表：先读桶 →（若条件打开）套管理员规则 →（可选）套本地 chip |
| 改何时 | 管理员改规则/开关立即全局生效；用户点选 chip 只影响自己下次进入 |
| 不做什么 | 用户 chip 不改变采集桶；不替代投注引擎 |

建议存储：`localStorage` 分产品 key（或用户级服务端偏好）：

- `yuce.tennis.prematch.filters.v1`
- `yuce.tennis.inplay.filters.v1`
- `yuce.tennis.settled.filters.v1`

## 4.2 盘前条件过滤（目标 UI）

### 4.3.1 盘中「现差」chip（单独一行，二选一）

盘中现差 **不是** 拆成 Top10/20/50/100 多个 chip，而是 **一行两个选项**：

| 选项 | 含义 |
|------|------|
| **不限** | 不做现差过滤 |
| **分档达标** | 选中后，按强者所在档位套用下列规则（整套一起生效） |

**「分档达标」规则（现差 = 弱现 − 强现）：**

| 强者现排所在档 | 须满足 |
|----------------|--------|
| ≤10（Top10） | 现差 ≥ 20 |
| ≤20（Top20，且非上档） | 现差 ≥ 30 |
| ≤50（Top50，且非上档） | 现差 ≥ 50 |
| ≤100（Top100，且非上档） | 现差 ≥ 150 |

判定：先看强者落在哪一档，再用该档阈值过滤；不满足则列表隐藏。

**与默认规则的关系：**

- 用户点选「不限」或「分档达标」后，写入 `yuce.tennis.inplay.filters.v1`。  
- **下次进入盘中，默认沿用上次选择**（与其它 chip 相同）。  
- 仅首次进入、尚未选过时，现差默认为 **不限**。

## 4.4 默认值（首次进入、尚未选过）

| 产品 | 默认 |
|------|------|

| 盘中 | 巡回=全部，PM=全部，强现=≤100，现差=**不限**（可选改为「分档达标」并持久化为默认） |
| 盘后 | 巡回=全部，PM=全部，强现=≤100，盈亏标记=全部 |

用户改过之后：**以用户选择为准**，作为该产品列表的默认过滤，直到再改。

| 现象 | 先查 |

# 九、下注引擎（策略执行）

> 权威策略来源：原 `docs/strategy.md`（已并入本文）。适用于 **盘中网球** 自动买/止损（投注引擎默认规则包）。  
> **须管理员「投注打开」** 后才执行；规则由管理员在投注引擎中配置，未改时以本节为准。  
> 引擎依赖：建场/排名来自采集引擎（IPWO → Sofascore）；盘中价来自 tick（直连 Polymarket）。

## 9.1 买入条件（须同时满足）

> 本节「排位差」= **现差**（弱者现排 − 强者现排）。

1. 判断当前选手（强侧）排名是否在前 **10** 名以内。  
2. 若排名在前 10 以内，判断双方排位差是否 **大于 20**。  
3. 若排名不在前 10 以内，判断当前排名是否在前 **25** 名以内。  
4. 若排名在前 25 以内，判断双方排位差是否 **大于 30**。  
5. 若排位差不满足条件，终止流程，不执行任何操作。  
6. 判断第一盘比赛结果是否为 **强侧赢**。  
7. 判断 Polymarket 上该侧赔率是否 **低于 91%**（&lt;91¢）。  
8. 以上全部满足 → **执行买入**。  
9. 买入后，开始实时监控比赛进度与比分（走盘中 tick + 引擎轮询）。

摘要：`(现≤10 且 现差>20) 或 (现≤25 且 现差>30)` · 赢首盘 · PM&lt;91¢ · 只买一次。

## 9.2 止损条件（BO3）

10. 判断赛制是否为 BO3。  
11. 若是 BO3，判断当前是否为 **第三盘**。  
12. 若是第三盘，判断强方 **局比分** 是否落后于弱方。  
13. 若落后，判断弱方局分是否领先强方 **超过 2 局**（**弱−强 &gt; 2**，即至少领先 3 局；不是 ≥2）。  
14. 满足 → **立即止损**。

## 9.3 止损条件（BO5 — 路径 A：盘分曾到 2:0）

> 前提：买入后强者已赢第一盘（1:0）；第二盘强者再赢 → 盘分 2:0。  
> 若 2:0 后强者再赢第三盘直接结束 → **不触发止损**，持有至结束。

15. 判断当前是否为第三盘。  
16. 若强者输掉第三盘，盘分变为 2:1，进入第四盘。  
17. 若强者赢下第四盘（3:1）→ 强者赢，持有至结束。  
18. 若强者输掉第四盘，盘分变为 2:2，进入第五盘（决胜盘）。  
19. 在第五盘中，判断强方局比分是否落后于弱方。  
20. 若落后，判断弱方局分是否领先强方超过 2 局（弱−强 &gt; 2）。  
21. 满足 → **立即止损**。  
22. 若赢下第五盘 → 强者赢，持有至结束。

## 9.4 止损条件（BO5 — 路径 B：盘分 1:1）

> 前提：强者先赢第一盘（1:0），第二盘强者输，盘分 1:1。

23. 判断当前是否为第三盘。  
24. 若强者赢下第三盘，盘分变为 2:1，**转入路径 A 自「进入第四盘」起的逻辑**（上节第 16 步之后：第四盘赢则结束；第四盘输→2:2→第五盘局分止损）。  
25. 若强者输掉第三盘，盘分变为 1:2（弱者领先），进入第四盘。  
26. **【关键止损点】** 在第四盘中，判断强方局比分是否落后于弱方。  
27. **【关键止损点】** 若落后，判断弱方局分是否领先强方超过 2 局（弱−强 &gt; 2）。  
28. **【关键止损点】** 满足 → **立即止损**。  
29. 若第四盘局比分未落后超过 2 局，继续：强者赢下第四盘 → 盘分 2:2，进入第五盘；强者输掉第四盘 → 盘分 1:3 比赛结束，**不触发止损，持有至结算**。  
30. 在第五盘中，判断强方局比分是否落后于弱方。  
31. 若落后，判断弱方局分是否领先强方超过 2 局（弱−强 &gt; 2）。  
32. 满足 → **立即止损**。  
33. 若赢下第五盘 → 强者赢，持有至结束。

## 9.5 通用规则

34. 所有止损中的「比分」均指 **局比分（Game Score）**，非盘分；局差条件统一为 **弱−强 &gt; 2**。  
35. 买入只在满足条件时执行 **一次**，之后不再重复买入。  
36. 未触发任何止损时，**持仓至比赛结束**。

## 9.6 引擎执行要点

| 项 | 约定 |
|----|------|
| 归属 | **投注引擎**（管理员统一管理） |
| 前置 | 管理员 **投注打开**；采集引擎在跑 |
| 产品 | 默认 `tennis-inplay`（盘前若配置自动买则同引擎） |
| 买 | `POST /api/tennis-inplay/trade/batch`（或盘前 batch） |
| 卖（止损） | `POST /api/tennis-inplay/trade/sell`（建议全平） |
| 去重 | `autoPlacedIds` / `autoSoldIds`（目标迁服务端仓位） |
| 调度 | tick 更新后评估；**先止损再买入** |
| 与条件引擎 | **互不依赖**：条件只筛列表；投注用本引擎规则直接过滤采集数据下单 |
| 与用户 chip | **无关**；chip 只影响个人列表二次筛 |

# 十、条件层与引擎层分离设计（草案）

三引擎统一在 **管理员** 下；列表 **用户 / 代理 / 管理员** 均可看。

| 层 | 负责 | 谁管 |
|----|------|------|
| **采集引擎** | 全量、tick、迁桶 | 管理员启停 |
| **条件引擎** | 规则 + **条件打开** → 筛选列表/候选 | 管理员 |
| **投注引擎** | 规则 + **投注打开** → 自动买/止损（§九） | 管理员 |
| **盘后统计** | 合计 / 盘前 / 盘中盈亏比 | 只读消费成交 |

规则包建议：`inplay-entry-v2`（§9.1）、`inplay-exit-v2`（§9.2–9.5）。  

演进：Phase A 前端抽 rules → Phase B 引擎服务端 + 管理员开关 → 盘后 stats API。
