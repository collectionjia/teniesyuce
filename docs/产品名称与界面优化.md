# 产品名称与界面优化

从订阅者视角看：这个站卖的是开赛前的方向判断，不是一份数据后台。当前名称和界面还在用「平台 / 数据产品」说话，订阅者进门后要自己猜买到的是什么。

## 现在实际在用的名字

| 位置 | 现在的文案 | 订阅者会理解成 |
| --- | --- | --- |
| 浏览器标题、登录副标题 | 数据分析平台 | 一个内部看数的后台 |
| 登录主标 | YUCE.BID | 品牌，但看不出卖什么 |
| 登录导语 | 整合多源数据与结构化指标，辅助研判与决策 | 工具说明，不是购买理由 |
| 首页标题 | 数据产品 | 商品货架，没有场景 |
| 网球 | 按未开赛 / 比赛中 / 完赛等阶段拆开 | 知道是赛前还是赛中 |
| Dota2、NFL | 只有项目名 | 像一个数据频道，看不出赛前指导 |
| 列表标记 | 优、外、HC、过线、Elo差 | 内部术语，要对照说明才懂 |

登录页已经有品牌字 **YUCE.BID**。缺的是一句订阅者能复述的产品承诺。

## 名称建议

**站名保持 YUCE.BID，对外副标题改成「赛前方向」。**

浏览器标题、登录副标题、首页标题都从「数据分析平台 / 数据产品」换成「赛前方向」。登录导语改成：开赛前给出模型方向，并标出是否与盘口一致。

**商品名用「项目 + 赛前方向」。**

- Dota2 → **Dota2 赛前方向**
- NFL → **NFL 赛前方向**
- 网球未开赛产品与这两项对齐，名称里保留「赛前」，不要只写项目或「数据」

卡片下的一句说明统一为：开赛前给出模型方向，并标出是否与盘口一致。

比赛中、完赛、BTC 看板继续用阶段或主题命名，不要并进「赛前方向」。首页若混放，订阅者会以为每个商品都是同一件事。

## 界面优先改的四处

### 1. 首页先回答「我买到什么」

商品卡现在是图标、名字、月价、订阅状态。订阅者还要再点进去才知道有没有赛前方向。

卡片上直接显示三样东西：项目、阶段（赛前）、一句话结果（例如今日可看场次，或「方向已更新」）。价格留在卡片底部，不要当主标题。

搜索框占位从「搜索...」改成「搜索项目或赛前方向」。

### 2. 列表用订阅者的话，术语收进说明

订阅者要先看到结论，再看到依据。

- 主标记只用 **一致 / 不一致**，表示模型方向和盘口高价侧是否相同
- 「优」改成队名本身高亮，或写成「模型看好」
- HC、过线、Elo差放到字段说明或详情里，不作为列表第一眼

详情弹层结构已经和网球对齐，这一层可以留。列表仍比详情更像内部看板。

### 3. 赛前指导和交易分开

顶栏的「已配 / 账户」是下单钱包状态，和「要不要看这场方向」无关。未配置钱包的订阅者仍应能看方向；不能下单时，在批量操作处说明原因，不要让顶栏看起来像还没开通产品。

产品详情里，方向区在上，下单条在下。未订阅时预览可以看列表结构，方向标记保持订阅后可见，这和现在的会员闸一致。

### 4. 订阅者界面和运营后台分开

同一套壳里同时有首页商品、五引擎、调度中心、采集代理。订阅者底部只要「首页」和「我的」。引擎、调度、密钥留在管理入口，不要出现在订阅者的首页标题和空状态文案里。

## 建议顺序

1. 改站名副标题和首页标题，商品改成「Dota2 赛前方向」「NFL 赛前方向」。
2. 商品卡补上阶段和一句话说明。
3. 列表主标记收成一致 / 不一致，其余术语进详情说明。
4. 顶栏钱包和下单与「看方向」分开。

前两步只改文案和卡片信息，订阅者下次打开就能对上产品是做什么的。
