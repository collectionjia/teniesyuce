## 3. 方法论

### 3.1 审计三维

| 维度 | 目的 | 方法 |
|------|------|------|
| A. 身份真实性 | 声明模型 = 实际调用模型 | 核对上游响应 `model` / 账单 / request_id |
| B. 未掺水 | 未静默换成更小/更便宜模型 | 路由配置审计 + 抽样一致性 + 成本区间 |
| C. 未显著降智 | 相对官方同版本无明显能力塌陷 | 固定题库双盲/对照测试 |

### 3.2 采样设计

| 项 | 值 |
|----|-----|
| 采样频率 | 一次性：【连续 N 天，每天 M 次】；按月：【每日/每周】 |
| 覆盖时段 | 【含业务高峰 HH:MM–HH:MM】 |
| 每模型有效请求数 | ≥【建议 ≥30，重要客户 ≥100】 |
| 租户/Key | 【客户专用 Key / 专用路由】 |
| 随机性控制 | temperature=【0 或固定】；同一题重复【K】次取众数或均值 |

### 3.3 通过/失败阈值（签约前建议与客户对齐）

| 指标 | 通过条件（示例，请改成合同值） |
|------|--------------------------------|
| model 字段一致率 | = 100%（不一致即失败） |
| 路由到声明外模型次数 | = 0 |
| 对照准确率相对官方落差 | ≤【5】个百分点 |
| 格式遵循率相对官方落差 | ≤【5】个百分点 |
| 异常拒答率升幅 | ≤【X】% |
| P95 延迟 | ≤【约定】或相对官方 ≤【Y】倍（仅作参考，非降智唯一依据） |

## 附：给销售/交付的一页纸话术

**客户问：怎么证明没掺水、没换模型？**  
→ 每次调用可核对上游返回的精确 model 与 request_id；审计报告附抽样表与配置映射。

**客户问：怎么证明没降智？**  
→ 同一题库、同一参数，官方直连 vs 你们入口对照；差值不超过合同阈值。

**客户问：以后会不会偷偷改？**  
→ 变更审批 + 月度抽检 + 不一致告警；重要客户可开放 model 字段回传。

**注意：** 避免承诺「永远与某月能力完全一致」；应承诺「路由至约定 model id，且相对官方同版本对照不超过阈值」。
