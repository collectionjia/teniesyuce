# 规则服务（`services/rules/`）

**实施优先级：③** · 端口：**9102**

详见 [项目模块与实施优先级 · P3](./项目模块与实施优先级.md#p3--优先级-3规则服务rules) · [模块边界与限制](./模块边界与限制.md)

---

## 职责

读 **采集服务** 写入的 Redis 三桶，按规则引擎配置筛选，输出 **可投注 matched 数据集**（含 `amountUsd`、规则组）。

- **未开赛** 与 **比赛中** 两套规则：**独立配置、独立开关、独立调度**
- **不做**：采集、下单、止损

---

## 两类规则

| | **未开赛 prematch** | **比赛中 inplay** |
|---|---------------------|-------------------|
| 数据 | prematch 桶 + 6h 全量 | inplay 桶 + 30s 比分/PM |
| 配置 | `condition.buckets.prematch` | `condition.buckets.inplay` |
| 条件 | tour、pm、排名差、强现排名 | + 盘分/局分、`requireWonFirstSet` 等 |
| 调度 | **2 小时** | **30 秒** |
| 结果 key | `tennis:rules:matched:prematch` | `tennis:rules:matched:inplay` |
| 下游 | betting prematch scan | betting inplay scan |

> settled 桶可选（复盘）；默认不参与自动投注。

**接口**：`POST /internal/rules/evaluate` 须带 `bucket: prematch | inplay`；**禁止跨桶混筛**。

---

## 执行需求

1. **REQ-R-01** 新建 `services/rules/`，端口 9102。
2. **REQ-R-02** `POST /internal/rules/evaluate`：按 `bucket` 走对应规则集。
3. **REQ-R-03** 配置：MySQL `tennis_engines_config` + Redis `tennis:engines:config:condition`。
4. **REQ-R-04** bucket 或 condition 全关 → `{ skipped: true }`。
5. **REQ-R-05** 逻辑迁移自 `tennisConditionApply.js`（组间 OR/AND、组内 AND）。
6. **REQ-R-06** 写 Redis matched；每条含 `groupId`、`groupName`、`amountUsd`、`bucket`、`evaluatedAt`。
7. **REQ-R-07** prematch：scheduler 每 2h 调一次。
8. **REQ-R-08** inplay：scheduler 每 30s 调一次。
9. **REQ-R-09** `GET /internal/rules/matched?bucket=` 供 betting 只读。
10. **REQ-R-10** `GET /health`；evaluate 返回 before/after、耗时、命中组。
11. **REQ-R-11** **默认配置**：沿用现网条件引擎各 bucket `groups[]`。
12. **REQ-R-12** **可修改配置**：后台改条件 → MySQL → Redis；每次 evaluate 读最新。

---

## 与投注金额

| 字段 | 来源 |
|------|------|
| `amountUsd` | 本服务从 `betting.amountUsd` 或组级覆盖写入 matched |
| betting | **只读** matched，不再自行算金额 |

---

## 输入 / 输出

```
读：{sport}:prematch|inplay 桶（首期 sport=tennis）
读：tennis:engines:config:condition
写：tennis:rules:matched:prematch|inplay
```
