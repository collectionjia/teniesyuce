# 止损服务（`services/stop-loss/`）

**实施优先级：⑤（最后一个实现）** · 端口：**9104**

详见 [项目模块与实施优先级 · P5](./项目模块与实施优先级.md#p5--优先级-5止损服务stop-loss) · [模块边界与限制](./模块边界与限制.md)

---

## 职责

对 **已下单且未平仓**、且赛事 **进行中（inplay）** 的订单，读最新比分与 PM 价，评估止损规则；触发则 **全部平仓**（100% 卖出）。

**不扫描**：未开赛 prematch 持仓、已完赛 settled、无 open 订单。

---

## 执行需求

1. **REQ-S-01** 新建 `services/stop-loss/`，端口 9104。
2. **REQ-S-02** `POST /internal/stop-loss/scan`：仅 `status=open` 且 `eventId ∈ inplay` 桶。
3. **REQ-S-03** 读 Redis inplay 比分 + `polymarketByEvent`（依赖 collect 30s partial）；数据 >60s 陈旧可告警。
4. **REQ-S-04** 止损规则：`betting.buckets.*.groups[].stopRules`。
5. **REQ-S-05** 触发 → **全平**，非部分减仓。
6. **REQ-S-06** 迁移 `tennisBettingEngine.js` `mode=stop`；PM CLOB 客户端。
7. **REQ-S-07** 平仓后 `status=closed/stopped`，记 `pnlUsd`、`closedAt`。
8. **REQ-S-08** `betting.enabled=false` → skip（与现 engineGate 一致）。
9. **REQ-S-09** **已下单 + 进行中**：scheduler 每 **30s**；prematch 持仓等开赛迁入 inplay 后再扫。
10. **REQ-S-10** `GET /health`；metrics：`openOrders`、`triggered`、`closed`、`errors[]`。
11. **REQ-S-11** **默认配置**：沿用现网各组 `stopRules`（BO3/BO5 等）。
12. **REQ-S-12** **可修改配置**：后台改止损 → MySQL → Redis；每次 scan 读最新。

---

## 数据流

```
读：MySQL/Redis open 订单
过滤：status=open 且 eventId ∈ inplay
读：inplay 比分 + PM（collect 30s 刷新）
评估：stopRules
执行：Polymarket 全平
写：订单 closed + pnl
```

---

## 与 scheduler

- 每 30s 触发 job
- 无符合条件的 open 订单 → `skipped: no inplay open orders`（不空跑 scan）

---

## Docker

- 最低依赖：Redis、MySQL
- 与 betting 共用 PM 钱包 env；**代码独立目录**，共享逻辑放 `packages/*`
