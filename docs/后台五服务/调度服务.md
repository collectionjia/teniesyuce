# 调度服务（`services/scheduler/`）

**实施优先级：①（第一个实现）** · 端口：**9105**

详见 [项目模块与实施优先级 · P1](./项目模块与实施优先级.md#p1--优先级-1调度服务scheduler) · [模块边界与限制](./模块边界与限制.md)

---

## 职责

**唯一** 定时触发入口；轮询 MySQL `scheduler_jobs`，到期则 **HTTP 调用** collect / rules / betting / stop-loss 的 internal 接口。

业务服务 **不自建 cron**。

---

## 调度表

| 任务 | 目标 | 频率 | 前置条件 |
|------|------|------|----------|
| 整体采集 | collect · full | **6h** | 采集引擎开 |
| 部分采集 | collect · partial | **30s** | 采集引擎开 |
| 未开赛规则 | rules · evaluate(prematch) | **2h** | `condition.buckets.prematch.enabled` |
| 比赛中规则 | rules · evaluate(inplay) | **30s** | `condition.buckets.inplay.enabled` |
| 盘前投注 | betting · scan(prematch) | **2h** | 规则 + 投注引擎开 |
| 盘中投注 | betting · scan(inplay) | **30s** | 规则 + 投注引擎开 |
| 止损 | stop-loss · scan | **30s** | 投注引擎开；**有 inplay open 订单** |

> 同 tick 建议顺序：**partial → rules → betting → stop-loss**（见 [模块边界与限制 §8](./模块边界与限制.md#8-调度顺序同-tick-内)）。

## 执行需求

1. **REQ-SCH-01** 新建 `services/scheduler/`，端口 9105；迁移 `schedulerLoop.js`。
2. **REQ-SCH-02** 任务存 MySQL `scheduler_jobs`；管理 API 可由 server 代理。
3. **REQ-SCH-03** loop 每 1～5s 轮询；`interval_sec`：21600 / 7200 / 30。
4. **REQ-SCH-04** HTTP 调用（禁止 `require` 业务模块）：
   - collect → `POST /internal/collect/full|partial`（`sport` 默认 tennis）
   - rules → `POST /internal/rules/evaluate`
   - betting → `POST /internal/betting/scan`
   - stop-loss → `POST /internal/stop-loss/scan`
5. **REQ-SCH-05** `skip_if_running` + `mutex_key`；manual 可并行。
6. **REQ-SCH-06** 引擎门禁读 `tennis:engines:config`；止损无 open inplay 订单则 skip。
7. **REQ-SCH-07** 空库 seed 预设 job：

   | job_id | interval_sec | enabled 默认 |
   |--------|--------------|--------------|
   | job_collect_top100 | 21600 | 1 |
   | job_collect_partial | 30 | 1 |
   | job_rules_prematch | 7200 | 0 |
   | job_rules_inplay | 30 | 0 |
   | job_bet_prematch | 7200 | 0 |
   | job_bet_inplay | 30 | 0 |
   | job_stop_loss | 30 | 0 |

8. **REQ-SCH-08** 运行记录写 `scheduler_runs`。
9. **REQ-SCH-09** `POST /internal/scheduler/run/:jobId` 立即执行。
10. **REQ-SCH-10** 从 `server/index.js` **移除** 内嵌 `schedulerLoop` 与 `tennisInplayTickLoop`。
11. **REQ-SCH-11** **默认配置**：优先沿用现网 `scheduler_jobs`。
12. **REQ-SCH-12** **可修改配置**：调度中心改间隔/启停 → MySQL；loop 秒级生效。

## 环境变量（必填）

| 变量 | 说明 |
|------|------|
| `COLLECT_URL` | 如 `http://collect:9101` |
| `RULES_URL` | 9102 |
| `BETTING_URL` | 9103 |
| `STOP_LOSS_URL` | 9104 |
| `REDIS_URL` / `MYSQL_URL` | 基础设施 |
| `INTERNAL_SERVICE_TOKEN` | 调 internal API |

多 sport 采集：job `params_json` 增 `{ "sport": "nba" }`，不改 HTTP 路径。

- 可 **只部署 scheduler + collect** 最小拓扑
